# xskill generate

## 一句话

连接团队服务器或公网实例后，用一句自然语言指令让服务器新建 Skill，或按你的要求改写已有 Skill。

## 什么时候用

- 你知道该有一条技能，但不想自己从零写 `SKILL.md`
- 现有技能不够用，想按你的要求改一版
- 希望生成时优先参考某几位同事的经验

`generate` 不是 standalone 命令。使用前必须先运行 `xskill connect`，让本机成为已认证的 team client。

## 怎么用

先连上团队（或公网实例），然后：

```bash
xskill generate "把处理发票报销的步骤写成技能"
```

只想参考某些人的会话时，带上工号或用户名（逗号分隔）：

```bash
xskill generate --name alice,bob "把他们处理发布失败的办法写成技能"
```

`--name` 是优先阅读提示，不是访问范围过滤器。代理会先参考 `alice` 和 `bob` 的轨迹，但仍可搜索服务器允许它读取的其他轨迹与已有 Skill。不要把这个参数当成隐私隔离或权限控制。

## 服务器会做什么

1. CLI 提交指令并打印 generate job ID。
2. 任务进入 SkillEdit 工作池；没有空闲席位时会显示「仍在排队」，开始后显示「仍在执行」并持续输出日志。
3. GenerateAgent 搜索允许读取的已有 Skill 和轨迹证据，判断应该新建还是改写。
4. 新建时写出完整的 `SKILL.md`，必要时补充 `scripts/` 或 `references/`；改写已有文件时会先读取再编辑。
5. 每个生成结果直接提交到对应 Skill 的 `main` 分支，不进入 `staging`，也不参加 canary A/B。提交信息会记录发起人的用户 ID。
6. CLI 最后列出生成的 Skill；服务器会在推荐槽位配额允许时把它们钉到发起人的推荐列表。钉选失败不会撤销已经成功的生成提交。

如果任务结束却没有提交任何 Skill，整次 generate 会被报告为失败，而不是显示一个没有产物的成功结果。

## 和相近命令的差别

| 命令 | 差别 |
| --- | --- |
| `xskill upload` | 你已经有一份写好的技能文件夹，发给大家搜。generate 是让服务器代写。 |
| `xskill import` | 把现成技能收进正式技能库。generate 是新建或改写。 |
| 手改自动上传 | 你自己改本地文件，改动进入隔离的 `user-staging/<client_id>` 草稿。generate 是你下指令、系统修改并直接提交 `main`。 |

## 排错

- 未运行 `xskill connect`：CLI 无法取得 team client 连接，请先连接服务器。
- 指令为空：CLI 会拒绝请求；引号中需要有明确的生成或修改目标。
- 服务器版本太旧：出现“不支持 generate”时，请管理员升级 server。
- 网络或服务器中断：检查连接和 server 状态后重新提交；job 日志流中断不会在本机生成 Skill。
- 长时间没有新日志：任务可能仍在排队或模型仍在执行，CLI 的周期状态提示会区分这两种情况。
- 显示“没有提交任何 skill”：代理没有产生有效提交，请收窄目标、补充必要上下文后重试。

## 安全与隐私

生成结果会进入团队 Skill 库，成为可复用内容。不要在指令或准备供生成器参考的轨迹中放入密钥、token、密码、私有内网地址、身份证件号码或其他个人敏感信息；示例和值应改用占位符。
